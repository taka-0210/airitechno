# アイリテクノ Webサイトリニューアル方針

更新日: 2026-08-10

## 1. この資料の目的

既存のプロ厨房HITサイトを、本部の情報発信を中心としたサイトから、直営店・FC店を含む「総合厨房機器サイト」へ再構築するための判断基準を定める。

既存ページは一括して移植しない。情報の対象者、運営主体、更新元を整理し、必要な内容を新しいサイト構造へ組み替える。

## 2. 目指すサイト

新サイトは、次の役割を持つ。

- 全国・各地域の利用者が厨房機器を探せる
- 新品・中古品の購入と厨房づくりをまとめて相談でき、買取希望者を専門サイトへ案内できる
- 各店舗の在庫、所在地、対応地域、特徴が分かる
- 導入事例や専門情報から、グループ全体への信頼を形成する
- 商品、店舗、記事などの情報を一元管理できる
- 本部とFC店のどちらか一方に偏らず、プロ厨房HIT全体の価値を伝える

基本の見せ方は「本部から各店へ情報を配るサイト」ではなく、「利用者が地域や目的から最適な商品・店舗・サービスへたどり着くサイト」とする。

### 2.1 ブランドの中心

プロ厨房HITを、単に厨房機器を販売する店ではなく、**厨房機器の販売から厨房設計、開業準備まで支援できる厨房づくりのパートナー**として位置付ける。

ブランドの中心となる約束は次のとおりとする。

> 機器を売るだけではなく、その店が営業を始められる厨房を一緒につくる。

「開業支援に強い」という表現だけで終わらせず、その理由を実績・仕組み・仕事の進め方によって具体的に伝える。

### 2.2 開業支援に強い理由

#### 全店に蓄積された飲食支援の経験

- 本部だけでなく、FC店を含む各店が長年にわたり飲食店を支援してきた
- 新規開業、移転、改装、機器入替、買取など、多様な現場を経験している
- 地域や業態ごとの知識を、プロ厨房HIT全体の支援力として活用できる

個別企業や本部だけの実績として語らず、「各地域の店舗が持つ経験を結集できるネットワーク」として表現する。

#### 独自システム「厨房君」

プロ厨房HITが開発した独自システム「厨房君」を、業務の中心機能として位置付ける。

- 各店の商品・在庫情報を一元管理する
- 日々蓄積される商品情報をWebサイトへ反映する
- 店舗を越えて、条件に合う厨房機器を探せる
- 現場の経験と商品データを結び付け、提案を支える

厨房君は単なる在庫管理システムとしてではなく、グループの経験と商品をつなぎ、より良い厨房提案を可能にする基盤として伝える。

ただし、利用者に対して「厨房君があるから必ず最適な設計になる」など、システムだけで品質を保証する表現は避ける。厨房君の情報と、担当者の経験・設計・打ち合わせを組み合わせることに価値がある。

### 2.3 プロ厨房HITが考える厨房づくり

厨房は、必要そうな商品を集めるだけでは完成しない。

- 店舗の業態と提供メニュー
- 席数と想定客数
- 調理・盛付・配膳・洗浄の動線
- 作業人数と役割
- 給排水、電気、ガス、換気などの設備条件
- 建物の寸法、搬入経路、法令・衛生面
- 開業予算と将来の運用コスト

これらを確認したうえで、機器の選定と配置を行う必要がある。そのため、プロ厨房HITでは次のような進め方をブランド体験として示す。

1. 開業計画、業態、メニュー、予算のヒアリング
2. 現地確認と必要条件の整理
3. 3Dレイアウトによる厨房イメージの共有
4. CAD図面を使用した寸法・設備・動線の検討
5. 図面を見ながら打ち合わせと修正
6. 新品・中古品を組み合わせた機器の提案
7. 搬入、設置、開業に向けた準備
8. 開業後の入替、修理、買取などの継続支援

3Dレイアウトは完成イメージを共有する手段、CAD図面は寸法や設備条件を詰める手段として、それぞれの役割が利用者に伝わるようにする。

### 2.4 ブランドメッセージの候補

中心メッセージの第一候補:

> 厨房機器を売るだけじゃない。繁盛店を支える厨房を、一緒につくる。

補助メッセージの候補:

- 商品探しから、厨房設計、開業後まで。
- 全国の現場経験と「厨房君」で、あなたの厨房づくりを支える。
- 3DとCADで、開業前に厨房の動きまで考える。
- 新品も中古も。予算と営業に合う厨房を提案する。

実際のキャッチコピーは、対応可能なサービス範囲と各店の運用を確認したうえで決定する。

### 2.5 Webサイトでの見せ方

トップページでは、商品検索だけを主役にせず、以下の順序で価値を伝える。

1. 厨房機器の購入と開業・厨房づくりを相談できること
2. 商品を探す導線と、厨房づくりを相談する導線
3. 3Dレイアウト・CAD図面を含む支援の流れ
4. 導入事例と利用者の声
5. 厨房君による豊富な商品・在庫情報
6. 地域の相談窓口となる店舗一覧

「開業支援に強い」ことの根拠として、抽象的な宣伝文句ではなく、実際の図面、3Dレイアウト、施工前後の写真、担当者の説明、導入事例を掲載する。

各導入事例には、可能な範囲で次の情報を持たせる。

- 店舗の業態と地域
- 相談時の課題
- どのような考えでレイアウトしたか
- 新品・中古品の選定理由
- 3DレイアウトやCAD図面
- 搬入・設置時の工夫
- 完成後の厨房と利用者の声
- 担当店舗・担当者

これにより、商品の安さや在庫数だけで比較されるサイトから、提案力と開業支援力で選ばれるサイトへ転換する。

## 3. 情報設計の原則

### 3.1 本部情報は薄めるのではなく、役割を分ける

本部固有の情報を単純に削除すると、会社としての実績や信頼まで失われる。そのため、既存情報を次の3種類に分ける。

1. **グループ共通情報**
   - プロ厨房HITの強み
   - 商品の程度・保証
   - 配送・送料
   - 購入や買取の流れ
   - 厨房づくりに関する知識

2. **店舗・地域情報**
   - 店舗情報
   - 店舗別在庫
   - 対応地域
   - 店舗独自のお知らせや事例
   - 来店予約・相談窓口

3. **運営会社・本部情報**
   - 会社概要
   - 採用情報
   - 本部主催イベント
   - 経営・社内活動に関する記事

サイトの主導線にはグループ共通情報と店舗・地域情報を置き、運営会社固有の情報は会社情報や記事の適切な分類へ収める。

### 3.2 店舗を対等に扱う

- 店舗ページは共通テンプレートを使用する
- 直営・FCは運営上必要な場合のみ明示し、見た目の優劣を作らない
- 商品の店舗名から店舗詳細へ移動できるようにする
- 利用者の現在地、都道府県、郵便番号などから近隣店舗を探せる構成を想定する
- 全店共通サービスと店舗限定サービスを明確に区別する

### 3.3 情報の正本を一つにする

| 情報 | 正本 | 新サイトでの扱い |
|---|---|---|
| 商品・在庫・価格・状態 | 厨房君 | APIで同期・表示 |
| 商品画像・動画 | 厨房君 | API経由で表示 |
| 店舗基本情報 | CMS | 店舗ページ、商品ページ、予約で共通利用 |
| お知らせ・ブログ | CMS | 分類・対象店舗を付けて掲載 |
| 導入事例・お客様の声 | CMS | 業種、地域、店舗、サービスで分類 |
| 固定ページ | CMS | 管理画面から編集 |
| 来店予約 | 予約機能 | 店舗・日時・相談内容と紐付け |

同じ住所や営業時間などを複数ページへ直接入力しない。店舗マスターを参照して表示する。

## 4. 想定する主要導線

### 商品を探す

`トップ → 商品を探す → カテゴリ／条件検索 → 商品詳細 → 在庫店舗／問い合わせ`

商品一覧はグリッド表示と縦一覧表示を選択可能にする。商品詳細では画像・動画、価格、状態、仕様、在庫店舗、問い合わせを一体化する。

### 店舗を探す

`トップ → 店舗を探す → 地域／現在地 → 店舗詳細 → 在庫を見る／来店予約`

### 厨房について相談する

`トップ → 目的から探す → 新規開業／入替／買取／修理等 → サービス詳細 → 事例 → 相談`

### 実績から検討する

`トップ → 導入事例 → 業種／地域／担当店舗で絞込 → 事例詳細 → 相談`

### 買取サイトとの役割分担

厨房機器の買取は、別途リニューアルする買取専門サイトを正規の案内先とする。

本サイトでは買取サービスの詳細ページや査定フォームを重複して構築せず、次の入口だけを用意する。

- トップページまたは共通導線の買取案内バナー
- 「厨房機器を売りたい」利用者向けの短い説明
- 買取専門サイトへ移動することが分かるリンク表現

買取実績の記事は、搬出技術や厨房全体への対応力を示す場合に限り、本サイトの導入・現場事例として活用できる。査定方法、買取対象、対応地域、申込フォームなどの詳細情報は買取専門サイト側で管理する。

バナーのリンク先URL、サイト名、ロゴ、公開時期は、買取サイトのリニューアル内容が確定した段階で設定する。新しい買取サイトの公開前後でリンク切れが起きないよう、切替手順を別途定める。

## 6. 既存ページの判定基準

既存ページを棚卸しするときは、各ページを次のいずれかに分類する。

| 判定 | 内容 | 対応 |
|---|---|---|
| 継続 | 全店・利用者に必要 | 内容を整えて移行 |
| 共通化 | 本部目線だが全店で使える | 主語や表現をグループ共通へ変更 |
| 店舗化 | 特定店舗・地域の情報 | 店舗ページまたは店舗記事へ移動 |
| 会社化 | 運営会社・社内活動の情報 | 会社情報または企業記事へ移動 |
| 統合 | 類似ページが複数ある | 代表ページへ統合し旧URLから転送 |
| 再編集 | 情報価値はあるが古い・読みにくい | 最新情報で再構成 |
| 廃止 | 重複、期限切れ、現在の事業と不一致 | 非公開または適切なページへ転送 |

判定時には以下も記録する。

- 現在のURLとページ名
- ページの目的と対象者
- 本部固有か、全店共通か、店舗固有か
- 新サイトでの移行先URL
- CMSで編集する項目
- 使用画像・添付ファイル
- SEO上引き継ぐタイトル、説明、主要キーワード
- リダイレクトの要否
- 公開優先度

## 7. CMS化するコンテンツ

原則として、商品以外の公開情報も管理画面から更新できるようにする。

- 固定ページ
- 店舗
- お知らせ
- ブログ・お役立ち記事
- 導入事例・お客様の声
- サービス
- よくある質問
- バナー・特集
- おすすめ商品の選定
- 共通設定（電話番号、受付時間、SNS、フッター等）

記事には「全店共通／対象店舗」「地域」「業種」「サービス」「公開期間」を持たせる。これにより、本部発信と店舗発信を同じCMSで管理しながら、必要な場所へ出し分けられる。

## 8. 来店予約の基本方針

来店予約では次の情報を扱う。

- 希望店舗
- 希望日時（第1〜第3希望）
- 相談目的
- 探している商品・設備
- 開業／入替予定時期
- 氏名、会社・店舗名、連絡先
- 備考

初期段階は「予約確定」ではなく、希望を受け付けて店舗から折り返す方式が安全である。店舗ごとの営業日や担当者スケジュールをリアルタイム管理できる段階で、空き枠予約へ拡張する。

## 9. 移行の進め方

### フェーズ1: 棚卸し

- 既存URLを収集する
- ページ、記事、PDF、画像、フォームを分類する
- 本部固有・全店共通・店舗固有を判定する
- アクセスや検索流入を確認できる場合は移行優先度へ反映する

### フェーズ2: 情報設計

- 正式サイトマップを決定する
- CMSのコンテンツ型と入力項目を決める
- URL規則とリダイレクト表を作る
- 店舗・記事・商品間の関連付けを決める

### フェーズ3: 共通機能の構築

- 共通ヘッダー・フッター
- 商品検索・商品詳細
- 店舗一覧・店舗詳細
- 問い合わせ・来店予約
- CMS管理画面

### フェーズ4: コンテンツ移行

- 優先ページから再編集・登録する
- 画像や添付ファイルを移行する
- SEO情報とリダイレクトを設定する

### フェーズ5: 検証・公開

- 商品同期、検索、フォーム、表示を検証する
- 各店舗に店舗情報を確認してもらう
- 旧URLからの転送を確認する
- 公開後もアクセス状況を見て導線を改善する

## 10. 当面の判断

- 商品の正本は厨房君とし、新サイトが `rise-up.net` の商品APIを直接参照する
- 旧 `pro-chubo.com` APIは移行期間中の切り戻し手段として残す
- 既存サイトの記事や固定ページは、自動で全件公開せず棚卸し後に移行する
- 本部の実績は削除せず、全店に役立つ事例・知識へ再編集する
- 店舗情報、在庫、記事、予約を相互に結び付け、地域ごとの入口を作る
