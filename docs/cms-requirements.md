# 独自CMS 要件・コンテンツ設計

更新日: 2026-08-10

## 1. 目的

プロ厨房HITの直営店・FC店を含む総合厨房機器サイトを、日常業務の中で継続的に更新できる独自CMSを構築する。

CMSは汎用的なページ作成ツールではなく、次の関係を管理する業務システムとして設計する。

`店舗 ⇄ サービス ⇄ 導入事例・記事 ⇄ 厨房君の商品`

## 2. システムの役割分担

| 情報 | 正本 | CMSでの扱い |
|---|---|---|
| 商品、在庫、価格、状態 | 厨房君 | API参照のみ。CMSへ複製しない |
| 商品画像・動画 | 厨房君 | APIのURL・商品番号を参照 |
| 店舗 | CMS | 全コンテンツの基礎マスター |
| サービス | CMS | 店舗、事例、記事と関連付ける |
| 導入事例・お客様の声 | CMS | ブランドの中心コンテンツ |
| お知らせ・記事 | CMS | 用途別に分類して掲載 |
| FAQ・固定ページ | CMS | 編集・公開管理 |
| バナー・特集 | CMS | 掲載位置と期間を管理 |
| 来店予約・問い合わせ | CMSの受付機能 | 店舗、商品、相談目的と紐付ける |
| 買取の詳細・査定 | 買取専門サイト | 本CMSは案内バナーのみ管理 |

- 操作履歴
- プレビュー

### フェーズB: 導入事例とサービス

- 導入事例管理

- 3Dレイアウト、CAD図面、施工写真等の管理

### フェーズC: 記事・固定コンテンツ

- お知らせ・記事
- FAQ
- 固定ページ
- バナー・特集
- SEO設定

### フェーズD: 受付機能

- 来店予約
- 総合問い合わせ

## 5. 共通フィールド

各公開コンテンツは、可能な限り次の共通項目を持つ。

- 管理ID
- タイトル
- URLスラッグ
- 公開状態: 下書き／レビュー待ち／予約公開／公開／非公開／アーカイブ
- 公開日時
- 公開終了日時（任意）
- 作成者、最終更新者
- 作成日時、更新日時
- 概要
- 本文
- アイキャッチ画像
- SEOタイトル
- メタディスクリプション
- OGP画像
- canonical URL（必要時）
- 旧URL
- 対象店舗
- 表示順

公開データは物理削除を基本とせず、非公開またはアーカイブにする。

## 6. 店舗マスター

店舗はCMS構築の最初のコンテンツとし、他のデータから参照する。

### 基本情報

- 店舗ID
- 厨房君店舗ID
- 店舗名
- URLスラッグ
- 店舗区分: 直営／FC／営業所／倉庫等
- 公開状態
- 郵便番号
- 都道府県、市区町村、町域・番地、建物名
- 緯度・経度
- 電話、FAX、メール
- 営業時間
- 定休日・臨時休業案内
- 対応地域

### 店舗紹介

- キャッチコピー
- 店舗紹介
- 得意な業態・相談
- 対応サービス
- 取扱品目
- 売場面積
- 店長・スタッフ
- メイン画像、ギャラリー
- Googleマップ
- LINE、SNS、外部リンク

### 機能設定

- 店舗在庫を表示するか
- 来店予約を受け付けるか
- 相談を受け付けるか
- 通知先メールアドレス
- 予約上の注意
- 表示順

- お客様の声

## 8. 記事・お知らせ

記事種別:

- お知らせ
- お役立ち情報
- 商品・入荷情報
- イベント・実演会
- 店舗のお知らせ
- 会社・採用情報

追加項目:

- 記事種別
- 対象店舗
- 地域
- 業種
- 関連サービス
- 関連導入事例
- 関連商品番号
- イベント開催期間

導入事例は記事の一分類にせず、専用の入力項目を持つ独立コンテンツとする。

## 9. サービス

- サービス名
- 概要
- 利用者の課題
- 対応内容
- 対応の流れ
- 対応店舗・地域
- 料金・条件（掲載可能な場合）
- よくある質問
- 関連事例
- CTA種別とリンク先

厨房づくり・開業支援を中心とし、販売、設計、搬入・設置、入替、修理、飲食店ホームページ制作等を整理する。買取は専門サイトへの案内として管理する。

ホームページ制作サービスには、通常のサービス項目に加えて次の情報を設定できるようにする。

- 制作プラン・対応範囲
- 想定する利用者（新規開業、リニューアル等）
- 制作期間の目安
- 顧客が用意する素材
- 撮影、文章作成、ドメイン、サーバー、保守の対応可否
- 制作サイトURL
- 関連する厨房導入事例

制作実績を登録する場合は、顧客の許諾、サイトURL、公開画像、制作範囲を記録する。

## 10. バナー・特集

- 管理名
- 表示画像（PC・スマートフォン）
- 代替テキスト
- リンク先
- 外部リンク表示
- 掲載位置
- 掲載開始・終了日時
- 対象店舗
- 表示順
- 公開状態

買取サイトへのバナーもこの機能で管理し、リニューアル時に画像とリンクを差し替えられるようにする。

## 11. おすすめ商品

商品情報自体は保存せず、厨房君の商品番号を指定する。

- 商品番号
- 掲載範囲: 全体／対象店舗
- 紹介コメント
- 掲載期間
- 表示順

商品が販売済み・非公開になった場合はAPI応答を確認し、自動で掲載対象外とする。

## 12. 権限案

| 権限 | 想定範囲 |
|---|---|
| システム管理者 | 全機能、管理者、設定、移行、履歴 |
| 店舗管理者 | 所属店舗の情報・記事・事例の作成・編集・承認申請、予約・問い合わせ対応 |

FC店の利用を想定し、店舗管理者が他店舗の非公開情報や問い合わせを閲覧できないようにする。

CMSの権限はシステム管理者と店舗管理者の2種類だけとする。一般スタッフにはCMSアカウントを発行せず、記事原稿や写真等を店舗管理者へ渡す運用とする。

CMSユーザーには所属店舗を設定し、店舗管理者の検索、一覧、編集、受付データを所属店舗の範囲に制限する。システム管理者だけが権限や所属店舗を変更できる。

店舗共通の共有アカウントは、誰が操作したか判別できず、退職・異動時の管理も難しいため使用しない。店舗管理者の権限を持つ責任者ごとに個別アカウントを発行し、同じ店舗に必要最小限の複数責任者を設定できるようにする。

### 厨房君スタッフとの連携

厨房君とCMSは認証を共通化しない。

- 厨房君: スタッフID、所属店舗、表示名、役職、在籍状態、Web掲載可否等の正本
- CMS: ログイン用メールアドレス、パスワード、CMS権限、公開フローの正本

厨房君のスタッフ情報からCMSアカウントを自動作成しない。厨房君のログインID、パスワード、内部権限、個人情報は取得・保存しない。

CMS内にはWeb利用に必要な安全なスタッフディレクトリを設け、次の項目だけを同期する。

- 厨房君スタッフID
- 所属店舗
- 表示名
- 役職
- Web掲載用プロフィール・写真
- Web掲載可否
- 在籍・有効状態
- 最終同期日時

店舗の店長・責任者は、このスタッフディレクトリのうち、所属店舗が一致し、在籍中かつWeb掲載可能なスタッフから選択する。CMSには選択したスタッフIDと表示用の控えを保持し、異動・退職・掲載不可になった場合は管理画面へ警告する。

店舗管理者の異動・退職時は、システム管理者がCMSアカウントを無効化する。担当記事や操作履歴は削除せず、後任への引継ぎ記録を保持する。

## 13. 公開フロー

基本フロー:

`店舗管理者の下書き → システム管理者のレビュー・承認 → 公開／予約公開 → 非公開・アーカイブ`

初期はシステム管理者だけが公開できる方式を基本とする。店舗管理者は所属店舗のコンテンツを作成・編集して承認申請できるが、直接公開はできない。運用が安定した後も、公開権限の追加は個別に判断する。

## 14. メディア管理

- 用途、コンテンツ、代替テキスト、撮影者・権利情報を保持する
- 画像は自動リサイズし、元画像も必要に応じて保持する
- 3D・CAD・PDFは公開可否とダウンロード可否を管理する
- 顧客名、図面、店内写真は公開許諾を記録する
- ファイル名衝突を避ける

保存先は次を基本とする。

- `uploads/stores/<store-id>/`
- `uploads/cases/<case-id>/`
- `uploads/articles/<article-id>/`
- `uploads/services/<service-id>/`
- `uploads/banners/`

## 15. 非機能・安全要件

- PHP 8系で動作する
- パスワードは安全なハッシュで保存する
- ログイン試行制限、CSRF対策、セッション保護を行う
- アップロード形式、容量、画像内容を検証する
- 管理操作と公開状態の変更を記録する
- データベースとアップロードをバックアップする
- 問い合わせ等の個人情報へ権限外の利用者がアクセスできないようにする
- CSVや画面へ出力する際の式注入・HTML注入を防ぐ

## 16. 最初の実装単位

最初の完成単位は、次の状態とする。

1. 管理者がログインできる
2. 店舗を登録・編集・非公開にできる
3. 店舗画像を用途別ディレクトリへ保存できる
4. 店舗ページをプレビューできる
5. 公開した店舗が公開サイトへ表示される
6. 操作履歴が残る

この土台を検証後、導入事例へ展開する。

## 17. ローカル初期設定

管理画面URL:

`http://localhost/airitechno/public/admin/`

管理者がまだ存在しない場合、管理画面URLを開くと初期設定画面へ自動的に移動する。表示名、メールアドレス、12文字以上のパスワードを画面で登録する。最初の管理者が作成されると初期設定画面は自動的に無効になる。

CLIで作成・再設定する場合は、プロジェクト直下で次を実行する。パスワードは12文字以上とし、ソースやGitへ保存しない。

`C:\xampp\php\php.exe scripts\create-cms-admin.php admin@example.com "表示名"`

CMSデータベースは既定で `storage/cms/cms.sqlite` に生成される。この実データと `public/uploads/` 配下のアップロードはGit管理外とし、環境ごとにバックアップする。

公開URLのベースは `AIRITECHNO_PUBLIC_BASE_URL`、予約機能実装後のリンク先は `AIRITECHNO_RESERVATION_URL`（店舗スラッグの差し込みは `{store_slug}`）で設定する。
